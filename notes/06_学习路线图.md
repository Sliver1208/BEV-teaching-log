## 📌 Phase 2：Camera + LiDAR 融合（2026.10 - 11 月，6 周）

**目标**：在 BEVFormer 里加 LiDAR 分支，做前融合/后融合对比实验。这是你区别于 99% 候选人的核心。

### 任务清单

| # | 任务 | 做法 | 完成标志 |
|---|------|------|---------|
| 2.1 | 加 LiDAR 分支 | 在 [models/](file:///c:/Users/PC/Documents/trae_projects/bev/models/) 新建 `lidar_backbone.py`：点云 voxelize → 3D Sparse Conv（可用 MinkowskiEngine 或 spconv）→ BEV 特征 | 输出 [B, C, 50, 50] 的 LiDAR BEV |
| 2.2 | **前融合实验** | 相机 BEV + LiDAR BEV → concat → SE module → 送入 Encoder | 写进架构取舍清单 |
| 2.3 | **后融合实验** | 相机 BEV 先过 Encoder → LiDAR BEV 用 cross-attn 注入 → 对比效果 | 量化对比（合成数据上的检测 mAP） |
| 2.4 | 处理 LiDAR 稀疏性 | 前融合时加稀疏性掩码（只有有点的位置激活） | 解决 BEV 网格噪声问题 |
| 2.5 | 数据层加 LiDAR | 在 [data/dataset.py](file:///c:/Users/PC/Documents/trae_projects/bev/data/dataset.py) 的 SyntheticDataset 里生成合成点云 | dataloader 同时返回 image + lidar + calib |
| 2.6 | 整理《融合架构取舍清单》 | 前融合 vs 后融合对比表（参考 notes/05 里的模板） | 简历可用 |

### 关键设计决策（要写进清单）
```
问题：LiDAR 稀疏性导致前融合 BEV 有大量 0/噪声
方案 A：稀疏性掩码（只有有点的位置参与融合）
方案 B：LiDAR BEV 先过一个 MLP 补全再融合
方案 C：用 pillar 方式（PointPillars）替代 voxel，天然 2D

→ 你选哪个？为什么？这就是面试的加分题
```

### 检查点
- 能跑 Camera-only 和 Camera+LiDAR 两种模式
- 有量化对比：加了 LiDAR 后检测 mAP 提升多少
- 架构取舍清单完成（至少 3 个对比维度）

## 📌 Phase 3：VLA 空间学习分支 + MEM + 动作输出（2026.12 - 2027.02，10 周）

**目标**：把 BEV 感知底座升级成 VLA 的"空间学习分支"，解决老哥说的"VLA 执行能力差"。

### 任务清单

| # | 任务 | 做法 | 完成标志 |
|---|------|------|---------|
| 3.1 | 学 VLA 基础 | 读 RT-2、PaLM-E 论文，理解 VLM→action token 的机制 | 能画 VLA forward 流程图 |
| 3.2 | **BEV 注入 VLA 实验** | 在融合后的 BEV 特征后加：CLIP text encoder + cross-attn（BEV 做 Key/Value，text 做 Query）| 能让模型响应简单语言指令 |
| 3.3 | 加 Action Head | 替换 [models/head.py](file:///c:/Users/PC/Documents/trae_projects/bev/models/head.py) 的检测头，改成输出：方向角(离散分类) + 速度(回归) | 给定"向前走"指令，输出合理轨迹 |
| 3.4 | **MEM（记忆模块）** | 加 memory bank：存最近 N 帧 BEV + 关键帧，用当前 BEV 做检索式 attention 读取 | 对比有/无 MEM 的时序稳定性 |
| 3.5 | （可选）WAM 入门 | 读 GAIA-1 / DriveDreamer，理解生成式世界模型怎么预演未来 | 能讲清 WAM 在规划里的作用 |
| 3.6 | 跑通 mini VLA demo | 输入：合成图像 + 点云 + 语言指令"go forward" → 输出：BEV 上的预测轨迹 | demo 视频/截图可放简历 |

### BEV 注入 VLA 的位置选择（要实验对比）
```
方案 A：BEV token 拼到 ViT 中间层 → 几何信息可能被语义稀释
方案 B：BEV 在 ViT 输出后做 cross-attn → 几何-语义解耦，推荐 ✅
方案 C：BEV 只在 action head 前注入 → 感知层没用到几何

→ 每个方案都要跑一下，对比效果，写进清单
```

### 检查点
- mini VLA demo 能响应至少 3 种语言指令（前进/左转/右转）
- MEM 模块能存储+检索历史帧
- 有 BEV 注入位置的对比实验数据
